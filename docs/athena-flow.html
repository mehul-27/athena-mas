EVIDENCE PATH
WHAT THE MODEL ACTUALLY SEES

Evidence is the product.

Search finds candidates. Fetching produces source text. Only recorded, relevant evidence reaches the analyst, writer and critic.

Question Explicit requirements: finding count, official sources, practical impact.
Route External → web + fetch. Local → RAG. Mixed → both. Calculation only when the task needs it.
MCP tools web_search returns discovery hints. fetch_page returns primary text. rag_search returns local chunks. calculate returns exact values.
record then read
EvidenceItem Every item keeps id, source type, source ref, content and retrieved_by. Full content stays on the Blackboard.
Prompt evidence Fetched pages get 2,000 chars; snippets, RAG and calculations get 600. Failed/empty fetches are excluded from citable evidence.
Analysis → Draft → Critique The writer cites source refs. The critic checks claims against evidence. Rejection is a result, not a failure to hide.
Snippet ≠ evidence A search result is a pointer. A claim that needs verification must rest on fetched page text.
Failed fetch ≠ evidence Errors and empty pages remain visible for audit, but never become citable support.
Missing evidence ≠ invention The writer states the gap. The reader gets an honest incomplete answer, not a fabricated one.
UNTRUSTED BY DEFAULT Fetched web text is wrapped as data. It cannot change the role, policy or tool rules. · PROVENANCE Every citable item carries a source_ref and the role that retrieved it.

ORCHESTRATION
FOUR PATTERNS / ONE CONTRACT

Four patterns. One contract.

All four produce the same Blackboard sections and comparable reports. The difference is how work and context travel.

Sequential

One researcher with all tools. The baseline.

planner→ researcher
all tools→ analyst→ writer→ critic

Parallel

Role-specific researchers run concurrently where planned.

planner→ rag web calc → analyst→ writer→ critic

Hierarchical

Plan roles are dispatched in order; one worker run per unique role.

planner→ unique workers
in plan order→ analyst→ writer→ critic
Recovery: high rejection + budget → targeted research → writer → critic again (bounded).

P2P

Context travels inline in A2A messages; the supervisor audits afterward.

planner
message→ researcher
message→ analyst
inline→ writer
inline→ critic
inline
Difference: no agent reads the Blackboard during reasoning; the supervisor writes audit records.

Missing critique is not approval. A missing or failed critic produces an incomplete result, never a verified one.
Disconnect is not success. The SSE stream and /log watchdog only mark success on valid completion evidence.
Evidence gaps stay visible. The report may be shorter than requested; it may not be invented.
