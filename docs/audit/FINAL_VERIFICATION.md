## Genuinely broken / mismatched wiring (summary)

1. **No empty-reply `retry` event in production.** `retry_empty_reply` (`retry_events.py:155`) has no non-test caller; `config/limited_models.py:101-118` (ADK) and `:247-256` / `:273-282` (CrewAI) retry with a doubled budget but emit only an `error` row via `reply_guard.note_empty_reply:24`. `docs/OBSERVABILITY.md:344` says this is implemented "in the real wrapper".
2. **`validate_message` is never invoked in production** (`guardrails/interagent.py:168`), so the A2A server applies only the HMAC check (`agents/crew_server.py:70-92,109`) and none of the mode/role/field/size validation `docs/SECURITY.md:23` claims; no `interagent` `guardrail` row is ever written.
3. **Chat-path guardrail rows are silently dropped** — no `Recorder` is installed in the API/chat process, so `record_flags` in `chat/service.py:112` (input), `:590` (tool output) and `:231` (output) resolves to `None` and writes nothing.
4. **Duplicate guardrail emitter**: `api/app.py:72-97` re-implements the event shape by hand instead of calling `guardrail_events.record_flags`, so the shared redaction path (`guardrail_events.py:73-82`) is bypassed on that path (the `Event` validator at `observability/events.py:96-102` still redacts `extra`).
5. `evidence` and `report_sanitize` pipeline labels are implemented and tested but unreachable in production (`tools/adapters.py:53`, `agents/report_sanitize.py:361` omit `pipeline_stage`) — disclosed, not a hidden defect.

## What is solid

`tool_call_guard` (one real explicit `retry` row at `limited_models.py:165`), `retry_audit` (installed in front of the recorder at `run.py:107`), `toolset_health` (load failure is an `error` event plus a degraded summary, `toolset_health.py:52-105`, `run.py:332`), `tool_args` (malformed-call guard on the real `before_tool_callback`, `researcher.py:265-276`), `mcp_stdio` (never-closed stderr sink at `researcher.py:169`), `cost` (read-side only, `telemetry_routes.py:227`), and Pydantic `FinalReport` as the structured output.
